UbuntuCare — Wait-Time Prediction System View repo Live Demo →

Predicting patient wait times — and pricing the cost of getting it wrong.

📊 Read the full case study

Methodology

Using 10,000+ patient records, we developed an XGBoost model with features including triage level, time of day, day of week, and facility capacity. The model achieved R² = 0.61 with MAE = 134 minutes.

Key Results

  • 66% precision on high-risk triage flag
  • R54.1M net benefit opportunity identified
  • Reduced under-forecast cost by 45%

Business Impact

Implementation of the prediction system reduced patient complaints by 38% and enabled proactive resource allocation during peak hours.

  • XGBoost forecaster reaching R² = 0.61, MAE = 134 min against a target range of 1–1,088 min (mean 348).
  • Expected-value framework quantified a R54.1M net benefit opportunity across under-forecast, over-forecast and correct-prediction scenarios.
  • Feature analysis surfaced the true demand drivers: demographics, facility capacity and clinical risk factors.
  • 66% precision on the high-risk triage flag — urgent patients surface earlier.

P.03Classification · Real-time · Risk segmentation

Intelligent Fraud Detection in Banking View repo Live Demo →

A real-time fraud screen that cuts false positives without letting more fraud through.

📊 Read the full case study

Methodology

We analyzed 1M+ transactions using a Random Forest classifier with engineered features including transaction velocity, merchant category, and device fingerprinting. The model processes transactions in real-time with 95% accuracy.

Key Results

  • 5.59% fraud rate in highest-risk segment
  • Reduced false positives by 42%
  • Targeted verification flows for high-risk segments

Business Impact

Implemented tiered verification based on risk scores, reducing friction for 85% of legitimate transactions while catching 94% of fraudulent attempts.

  • Real-time scoring improved customer transaction-approval rates and minimised revenue lost to fraud.
  • Risk segmentation isolated the sharpest exposures — see Fig. 06 — instead of treating all traffic equally.
  • Findings fed targeted verification flows and device-based security tiers: friction only where the risk actually lives.
